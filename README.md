# upkeep-site

The documentation site for [upkeep](https://github.com/owenbush/upkeep),
published at **<https://upkeep.owenbush.dev>**. Astro + Starlight.

## The documentation is not written here

Everything under `src/content/docs/{guide,reference,design}` is **pulled from
the upkeep repository at build time** by `scripts/sync-docs.mjs`, and is
gitignored here. Do not edit those files: the next build overwrites them.

That is deliberate, and it is worth stating why. This site used to keep its own
copy of the command table and the dashboard mockup. Both drifted — silently,
because nothing anywhere compared them to the tool. By the time anyone looked,
the table listed 11 of 27 commands, the whole issue loop and patch surface were
missing, and the mockup showed a column the data model no longer had.

Documentation beside the code gets reviewed in the same pull request as the
change that invalidates it. A copy in another repository does not. So:

| Change | Where |
| --- | --- |
| A guide, a reference page, the design docs | `docs/` in **owenbush/upkeep** |
| The command reference | Nowhere by hand — generated by `composer docs:commands` and gated in upkeep's CI |
| The landing page, theme, sidebar, this build | Here |

## Local development

Needs a checkout of upkeep beside this one (or pass its path):

```bash
npm install
npm run dev                       # syncs from ../upkeep, then serves
node scripts/sync-docs.mjs ~/code/upkeep   # or point it somewhere else
```

`npm run build` syncs and builds. The sync **fails the build** on a link that
points outside the synced set, rather than publishing a dead one.

## Deployment

GitHub Pages, via `.github/workflows/deploy.yml`, on push here, daily, or on
demand from the Actions tab. The daily run is what picks up documentation
merged in the upkeep repository; use "Run workflow" to publish one immediately.

**Requires a `DOCS_READ_TOKEN` repository secret** holding a token with read
access to `owenbush/upkeep`. The build checks that repository out, the job's
own `GITHUB_TOKEN` is scoped to this one, and upkeep is private while it is
unreleased — so without the secret the checkout gets a 404 from the API. The
workflow checks for it first and says so, rather than failing later with
"Not Found".

A missing token fails the build instead of deploying the site without its
documentation. Every sidebar entry would 404, and a stale site is coherent
where a hollow one is not — so the previous deploy stays up.
